# V3运行、接口与演示

当前交付范围：CLI和HTTP真实基线可运行、页面已联通；真实模型修复、Docker候选测试与独立复验尚未实际验收。原`ui/prototype`和v0.2配置/提示词保留；新页面位于`ui/app`，沿用原三栏布局与样式。现在登记leap及40道QuixBugs题目，其中2道原生慢测题暂禁用，不接受网页上传的任意目录或Shell命令。全文各模块的完成与缺失见[最新对照](V3全文完成情况与公开案例接入.md)，数据来源见[导入验收](QuixBugs数据集导入与验收.md)。

## 安装和启动

需要Python3.14（C执行器主动检查版本），按根README创建虚拟环境并安装`requirements-lock.txt`。锁文件来自本轮实际安装环境，包含FastAPI、uvicorn、httpx及pytest的确切版本。

```powershell
.\.venv\Scripts\python.exe -m app.cli doctor
.\.venv\Scripts\python.exe -m app.cli serve --port 8000
```

打开[本机页面](http://127.0.0.1:8000/)。仅监听127.0.0.1；不是多用户公网服务。任务状态与事件保存在`runs/platform/tasks.sqlite3`，每个run的原始产物在同目录下的独立run目录。可以用`CODE_FIX_RUN_ROOT`指定另一运行根目录。

本轮开发实际环境为`runs/v3-venv/Scripts/python.exe`，可直接代替上文`.venv`解释器运行。第一批浏览器验证使用8765和独立`runs/v3-browser-runs`；最新公开题目检查使用8000及默认任务库，保留原历史。

## 命令行验收

```powershell
python -m app.cli create-task --mode baseline --idempotency-key baseline-001
python -m app.cli start-task <返回的run_id>
python -m app.cli task-status <run_id>
python -m app.cli task-report <run_id>
python -m app.cli list-tasks
python -m app.cli list-projects
python -m app.cli create-task --project qb-gcd --mode baseline --max-calls 2 --total-seconds 60
```

预期：真实pytest为3过1败，1900年断言失败；任务stopped，final_result=not_run，model_api_called=false。同一幂等键重复创建返回同一run，已启动任务再次启动被拒绝。刷新页面只查询，不重新开始任务。

上述3过1败仅指leap。qb-get_factors、qb-gcd、qb-max_sublist_sum分别登记11、6、6项原生测试；它们的baseline也必须在Docker执行，当前无执行条件时blocked、工具调用0。公开题目baseline不调用模型，不要求模型密钥，不能因没有Docker改为宿主执行。模型修复模式同时要求模型与隔离条件。

现已扩充到40道公开题目，使用`list-projects`或`GET /api/v3/projects`查看完整名单。可用`python -m app.cli import-quixbugs`预览固定数据包，显式加`--write`才导入；默认不联网、不执行上游代码。原生测试数为静态预登记，实际收集待Docker核对；knapsack和levenshtein因慢测跳过策略暂禁用，不允许跳过后冒充全部通过。

异常退出后不会自动重放可能收费的任务。只有确认旧worker已经退出，才使用`python -m app.cli interrupt-task <run_id>`登记中断；这是操作员登记，不是杀进程命令。运行中可通过页面请求暂停/停止，在步骤边界生效；当前不提供暂停后自动续跑。

控制请求与状态事件一同提交；stop优先于后续pause。模型请求返回后、补丁应用前会再次检查控制和总时限；已经发出的请求仍保留调用与费用记录。控制不会立即杀死当前请求或测试。JSON报告使用同一数据库快照读取任务与事件。本轮真实基线HTTP暂停、证据包及14项新增测试见[状态控制验收](V3状态控制与证据验收.md)。

## 真实模型与执行前置（当前受阻）

先由队长明确模型服务商、模型名、每日USD费用上限、实际输入/输出单价及请求时限，再由操作者在启动服务的PowerShell中设置：

```powershell
$env:CODE_FIX_API_KEY = '<只在本机设置真实密钥，不提交Git>'
$env:CODE_FIX_MODEL = '<实际模型名>'
$env:CODE_FIX_BASE_URL = '<服务商HTTPS兼容接口根地址，例如以/v1结尾>'
$env:CODE_FIX_REQUEST_SECONDS = '<批准的正秒数，最多120>'
$env:CODE_FIX_DAILY_USD = '<批准的每日美元上限>'
$env:CODE_FIX_INPUT_USD_PER_MILLION = '<实际每百万输入token美元价>'
$env:CODE_FIX_OUTPUT_USD_PER_MILLION = '<实际每百万输出token美元价>'
$env:CODE_FIX_LIVE_APPROVED = '1'
```

占位值不是已批准预算，不可原样执行以代替确认。支持HTTPS Chat Completions兼容服务，使用`max_completion_tokens`；未实测各服务商差异。不读取`.env`文件，不隐式调用SDK，不继承系统代理，不接受HTTP重定向。单请求只尝试一次；传输失败或usage缺失将费用记unknown，停止新付费调用。账本使用队伍运行根目录共享SQLite，按北京时间日期累计；不能通过切换run重置。多台机器独立目录并不构成跨机器共享账本。

首次真实调用前必须核对单价和服务商计费差异，使用账本保守预留；显示估算费用而非服务商账单。未知费用需操作员核对账单后处理，当前未提供自动对账/人工对账UI，不能删除账本假装费用为0。API密钥不会写入请求日志或发送到浏览器。

Docker候选执行需要Linux容器引擎，且先取得不可信代码执行授权。在有Docker的执行机上进行：

```powershell
docker build -f docker/runner.Dockerfile -t codefix-runner-local docker
docker image inspect codefix-runner-local --format '{{.Id}}'
$env:CODE_FIX_DOCKER_IMAGE = '<上一步实际sha256镜像ID>'
$env:CODE_FIX_EXECUTION_APPROVED = '1'
```

本轮没有执行以上命令，也未批准其隔离状态。镜像固定到本机构建后的内容ID；构建可能联网下载基础镜像与pytest。运行路径禁止自动拉取镜像，每次任务先运行已知探针并记录实际容器配置，探针通过后才允许候选测试。容器无网络、非root、只读根目录、丢弃capabilities、限制CPU/内存/PID；代码、原生测试和入口只读挂载，报告写入有大小限制的容器tmpfs，通过受限输出传回，不提供宿主可写挂载或密钥。

Docker探针验证这些运行限制，不代表VM级隔离认证或对恶意代码的全面安全证明。模型候选与pytest处于同一容器Python进程，可影响自己的报告；结构化/JUnit交叉校验不能提供抵御蓄意伪造的安全保证。竞赛功能性测试与敌对代码评测必须区分。实际Docker路径及清理仍须目标机验收，未通过前不执行不可信代码。

配置齐备后：

```powershell
python -m app.cli create-task --mode repair --max-rounds 3
python -m app.cli start-task <run_id>
```

程序先检查模型配置和真实隔离条件；不满足时blocked且不发付费请求。流程为真实原始缺陷→修复员→补丁校验/应用→开发测试→检测员→调度员建议→程序规则动作。断言失败回定位员；语法错误回修复；环境暂停；超时/轮次上限停止。最终复验从原始干净副本应用最终完整文件，重跑同套冻结原生测试；不是隐藏测试，也不把最终结果反馈给模型。

## HTTP接口

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| GET | `/api/v3/session` | 本机页面取得写操作令牌 |
| GET | `/api/v3/health` | 配置与阻碍；不会把配置存在当成隔离已验证 |
| GET | `/api/v3/projects` | 41个登记题目的来源、预登记测试数、路径、隔离与准入阻碍 |
| POST | `/api/v3/tasks` | 验证并保存任务；可用Idempotency-Key防重复创建 |
| GET | `/api/v3/tasks` | 最近100个任务 |
| GET | `/api/v3/tasks/{run_id}` | 持久化状态与结果 |
| POST | `/api/v3/tasks/{run_id}/start` | 原子抢占，后台执行；重复返回409 |
| POST | `/api/v3/tasks/{run_id}/control` | `{"action":"pause"}`或stop；步骤边界生效 |
| GET | `/api/v3/tasks/{run_id}/events` | 按顺序查询真实事件 |
| GET | `/api/v3/tasks/{run_id}/report` | 下载JSON运行报告 |
| GET | `/api/v3/tasks/{run_id}/artifact?path=...` | 受限读取本run产物，拒绝越界和链接 |
| GET | `/api/v3/tasks/{run_id}/bundle` | 终态完整ZIP及SHA256清单，最多64MiB |

任务字段：description、project（leap及目录中40个qb-*标识，如qb-quicksort）、mode（baseline/repair）、max_rounds（1—3）、max_calls（1—30，模型调用）、total_seconds（1—1800）。未知字段拒绝。模型默认输出上限2048token、输入保守上限16000token；长日志仅提供当前开发片段。每个新候选都计轮次，不把失败候选计数清零。

写接口需要会话返回的`X-Codefix-Token`。服务拒绝跨站来源与不支持Host，只用于本机；没有远程账号管理/多用户身份认证。OpenAPI文档在[本机/docs](http://127.0.0.1:8000/docs)，写操作仍需提供令牌；建议使用页面或CLI操作。

## 真实演示与测试边界

1. 打开页面，选真实基线→创建→启动。
2. 查看真实run编号、1900年失败及3过1败；最终验收显示未运行。
3. 刷新页面，确认仍是同一编号；下载报告与证据ZIP，核对JUnit与sha256清单。
4. 未配置模型/Docker时选择真实修复，系统应blocked并给出具体阻碍，不能显示修复成功。
5. 配置和目标机隔离验收完成后，另跑真实模型案例并保存成功及失败记录；此前不统计模型修复成功率。

回归命令：`python -B -X utf8 -m pytest -q`和`node --test tests/ui_prototype.test.cjs`。编排成功/失败分支测试使用明确标记的测试替身，不代表模型或Docker执行；API基线测试与Edge页面操作确实启动了真实pytest。

已知限制：FastAPI依赖的Starlette对httpx TestClient给出一条弃用警告，当前测试通过；宿主软链接测试跳过；真实模型、Docker完整路径与候选独立复验未验收。没有新增公开数据集实验、成功率对照、复杂场景或暂停续跑。比赛评分、提交格式与正式演示要求仍需团队核实；PPT、美术和正式提交未交付。
