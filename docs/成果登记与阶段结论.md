## 一次运行登记一次 一次调用单独留证

[运行记录模板](../evaluation/run_record.template.json)是空模板，不是真实运行。由B程序生成实际记录，A登记到任务台账；暂未实现自动汇总时，A可根据原始证据人工汇总，但不能补造events.jsonl或模型调用记录。

实际JSON保存到本地runs/<run_id>/；每次模型/工具调用使用独立call_id和产物路径，重试不得覆盖旧文件。关键记录检查密钥、隐私等敏感信息后可放evidence/<run_id>/入库。模板中的template_only在真实记录中删除或设为false，样例ID和版本不能照抄。

实际记录终态字段统一为status，与RunSummary一致。limits_snapshot.daily_cost_limit为全队北京时间当天累计上限；max_tool_calls为单次运行上限，包含模型请求、网络重试和工具执行。费用账本跨run累积，不能新建运行后清零。

| 字段 | 从哪来 | 不知道怎么办 |
| --- | --- | --- |
| run_id、task_id、call_id、系统commit、配置版本 | B程序和Git | 找B确认，不猜；不同调用不得共用产物 |
| 任务来源、固定commit、允许路径、环境资格 | C记录 | 写未确认，不能默认允许自动执行 |
| 起点与修改后code_version | B/C计算 | 缺少则不能证明证据对应 |
| test_suite_version、expected_test_count | C冻结的测试清单 | 未确认时不能把零失败当通过 |
| counts.collected、passed、failed、errors、skipped | C执行器与原始报告 | 无法解析填null并说明原因，不猜0 |
| junit_path、junit_missing_reason | 独立call_id对应JUnit文件 | 缺失填null和原因，相关统计不可得也填null |
| 开发测试结论 | 实际执行证据 | 未执行写not_run；执行过但证据不完整写inconclusive |
| 独立验收结论 | C干净副本重跑固定原生测试 | 未执行写not_run；错误或超时为inconclusive，不是passed |
| 模型原始回复、实际应用补丁 | B本次运行文件 | 没有就登记证据缺失 |
| 调度动作、原因和触发证据 | Decision与Evidence | 不能只凭页面文字 |
| 超时与清理 | 执行器退出及子进程检查 | 清理未证实标待验，不继续自动执行 |
| 费用、Token、耗时 | API用量、日志、明确计费来源 | 费用未知写unknown、金额null，不能写0 |
| C复核结论 | C实际检查 | 未检查写not_run；证据未收到写待验 |

ToolResult.status保持ok / failed / timeout / blocked；验证结果使用passed / failed / not_run / inconclusive，不能混用。只有实际独立验收通过且版本对应，才能写最终success。JUnit缺失、零测试、收集失败、超时都不能靠“没有失败字样”判通过。具体草案见[接口确认清单](接口确认清单.md)，字段迁移仍待B/C确认。

## 成绩类型必须分开

run_type必须区分：

- model_repair：真实模型修复尝试，保留成功与失败。
- reference_check：参考答案或参考补丁环境验证，不计模型成绩。
- fault_injection：人为设置错误验证平台控制，不计模型成绩。
- tool_check：已知补丁、fixture或纯工具通路检查，不计模型成绩。
- human_reproduce：A按说明复跑，作为复现证据，不能重复增加模型修复成功数。

目标测试固定，不由Agent生成或修改。B/C可以写平台自身fixture和控制测试；这些证明执行器或调度器行为，不能记成QuixBugs模型修复结果。测试角色为确定性工具，定位和修复为LLM角色，reviewer关闭。

## 晚上阶段结论怎么填

11月1日填[当日记录](daily/2026-11-01.md)，不要覆盖10月31日历史。实际检查按[验收口径](acceptance.md)执行。

1. 记录准确系统提交、配置版本、任务及测试套件版本。
2. 已完成只列有证据支持的功能；输入材料写“材料已准备”，不写“功能已完成”。
3. 未通过/待验列缺口、负责人、下一步和检查时间；发送整改通知仍算待验。
4. 分别检查真实闭环、分支、停止、权限、版本、知识、独立验收和他人复跑，不凭其中一项替代全部。
5. 决定继续、缩减或暂停自动执行，写明原因和边界。
6. B/C复核技术事实，A确认；导师摘要由此摘录，不另编成绩。

继续：隔离可用，轻量闭环、证据分支与停止有效，其余缺口有计划。缩减：轻量主链路可用但复杂仓库或界面受阻，明确延后内容。暂停自动执行：隔离或状态管理不可用，或执行证据不足，先修执行器、不扩大自动任务。模型修复失败不等同执行器坏了；失败也保留。

## 版本与实验怎样留记录

同一任务、模型、提示词和预算上限下，升级前后分别留run_id与系统commit；不同任务的成绩不能证明版本提升。执行环境、预算、测试套件和样本未冻结前不批量运行。

闰年与少量算法题仅用于联调及初步尝试，不证明复杂平台能力或统计领先。正式实验按[实验协议](experiment-protocol.md)登记：固定1轮与动态最多3轮同时改变预算，不得把全部差异归因于调度；同预算上限对照、单Agent基线及成本分析分别记录。运行不完整和基础设施失败单列并保留，不能事后删除差成绩或临时换样本。
