## 两种模式与控制变量

| 项目 | 固定顺序流水线（T-040） | 证据驱动编排（T-034） |
| --- | --- | --- |
| 流程 | 预先冻结的Agent/工具顺序，失败后按相同顺序继续下一轮 | 按失败类型、测试证据和预算决定定位、修复、停止或移交 |
| 调度建议 | 推进建议仅留证，不改变预定义顺序；两组均允许保守pause/stop | 模型建议经独立程序调度层校验后执行，不能覆盖安全/版本/预算规则；允许保守pause/stop |
| 共同保护 | 成功后干净复验；预算/时限/隔离/权限/证据异常强制停止 | 同左；共同保护不是被消融掉的创新点 |
| 资源上限 | 与动态组相同的候选、模型调用、请求/工具/总时限及费用上限 | 同左；实际消耗可以不同并逐项报告 |

两组使用同任务、原始代码、冻结测试、模型及参数、可用角色/提示词版本、知识范围和环境；各自独立workspace及run_id，不沿用另一组补丁、对话、答案缓存或执行结果。不能给固定组额外参考答案，不能只给动态组更多尝试。角色实际调用顺序/跳过和每步理由都保留。模型不支持seed时写不支持，重复次数及运行顺序预先登记。

**旧“fixed=1个候选，dynamic最多3个”的比较不能作为调度收益的主证据。** T-023保留历史单候选诊断基线用途，暂缓；主比较由T-040实施。正式候选上限可同设3（在程序允许范围内），具体调用/费用等由A批准后冻结；同上限不要求实际调用数强行相等，提前停止节省的消耗正是待测指标。当前API保留mode=baseline/repair，以strategy=fixed/dynamic区分修复策略；未传策略默认dynamic，引用保存配置时策略以快照为准，冲突422。

## 指标、分母与图表

| 必报指标 | 统一计算口径 |
| --- | --- |
| 修复成功率 | 最终完整冻结测试实际通过题数/N；每组N为同一预登记任务数，未生成补丁/失败/超时/未完成保留在主表。缺测和跳过单列，不当完整成功 |
| 平均调用轮次 | 分别报告候选轮数和实际LLM请求次数，不混为一个数；均含失败任务，另报成功子集并标分母 |
| LLM调用成本 | 输入/输出token、实际请求次数（含失败与任何重试）、批准价格版本/币种、估算费用；与服务商账单口径区分，unknown不填0 |
| 单题耗时 | 从实际任务启动到终态，含预检、模型、开发测试和final；另列模型/工具耗时，镜像构建和排队单列。两组用同一计时定义 |
| 调度过程 | 动作/规则命中、有效重试、终止/移交原因、证据绑定完整性及实际分支；“无效调用”先定义再统计，不能事后凭感觉删掉调用 |

逐题表至少含project/run_id/策略/平台commit/模型与提示词/代码和套件/上限及实际消耗/开发与final/失败或移交原因/证据。汇总表及成本、耗时、请求次数图来自该表，每点可追到run；全部真实值齐备后再生成图表，不预填提升比例。真实失败保留；基础设施故障修复后另建run，额外有效子集分析须另报分母及排除理由。

要检验的是证据路由是否减少不必要调用、能否更早识别应停止或人工处理的情况，以及与修复效果的权衡；小样本结果不得推广为通用优势。模拟、可信闰年、参考检查、已知补丁和故障注入分表，不混入公开真实模型实验。

## 062：显式清单与双分母

正式首批按qb-get_factors→qb-gcd→qb-max_sublist_sum推进，一题配对核对后再扩展。freeze的同条件身份校验不允许用不同模型/指令/生成参数、价格、提交、测试/镜像或资源上限制造差异；相同配置内容而不同ID允许。正式、受控注入、离线夹具各自建scope，不能混算。清单中的失败、blocked与未运行不得删除；每题只登记一组固定/动态运行，不自动挑最好的一次。

平台提供计划组数、已有运行、已执行、成功、执行未成功、blocked、未运行，以及成功/计划、成功/已执行两个口径。只有产生登记baseline的工具证据才计已执行，前置blocked仍保留在计划。候选轮次以candidate_applied事件计，真实HTTP次数以model_api_called的agent_call计，不把模型建议次数或组件测试数当题数。费用按币种和状态保留，未知不填零；已知小计不等于总额。每个数值可通过run链接追溯，耗时取首started至finished，归档更新时间不改变它。对账后需新建快照，不改写旧图表。自动汇总不是C对证据来源、自然候选与正式实验分母的本人签收。
