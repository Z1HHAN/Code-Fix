# 证据登记与阶段结论规则

本页规定登记格式；实际任务状态唯一保存在[台账](当前开发任务台账.md)，真实运行原始材料只新增、不覆盖。

每个记录保留作者/角色/机器、实际日期、任务ID、main基线、被测代码commit、模型/提示词/配置/任务/套件/镜像版本、命令、run/call ID、阶段、结果与限制、日志/JUnit/JSON/diff/ZIP及SHA256。没有运行的字段写未运行/原因；未知金额写unknown，不代填签收。

证据使用已有`evidence/<日期>/<角色或主题>/<run_id>/`约定；本机完整`runs/`被忽略，不能把仅本机路径当成已经交付。大文件用团队可访问位置，登记访问方式与哈希。密钥、数据库、私人会话、参考答案不进入产品Agent上下文；评测端参考材料与模型可读资料隔离。

旧日期/旧代码的测试保留原结论，新代码另建run。一个批次失败后复跑仍保留初次失败；不删失败分母、不覆盖日志或把原型当平台。A只根据B/C交付更新本轮新增范围，并记录待复核分支与已合入main的差别。

## 阶段结论必须回答

1. 实际版本、任务及测试范围是什么？
2. 本人新做了什么，哪些是复用已有实现？
3. 实现/测试/独立验收分别到哪一步？
4. 哪些是平台、可信夹具、Docker资格、公开基线、真实模型、参考或模拟？
5. 哪些失败/受阻/未知，谁下一步处理？
6. A需要改哪些文档的哪个ID，依据何处？PPT/demo可展示什么？

[B/C分支规范](提交与维护规范.md)与[交付模板](提交与维护规范.md)是具体填报入口；[素材索引](版本与演示素材索引.md)只链接来源，不另编成绩。官方要求、隔离状态、费用授权由相应负责人真实确认，文档治理不替代。
