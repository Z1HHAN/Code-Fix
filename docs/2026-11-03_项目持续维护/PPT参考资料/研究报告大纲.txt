证据驱动的多 Agent 编排与验证平台 —— 面向 Python 软件缺陷修复场景
研究报告大纲（参考）
摘要
简述研究背景（大模型代码修复、单流水线智能体的局限）、研究思路：搭建定位-修复-测试多智能体协同链路，以测试证据作为调度依据构建自适应闭环；设计固定流水线对照实验；说明数据集、评价指标、主要结论；点明本研究聚焦多智能体编排调度策略验证。
关键词：多智能体编排；证据驱动调度；代码缺陷自动修复；大语言模型；闭环验证
正文部分
1 绪论
1.1 研究背景与意义
大模型在软件工程缺陷修复的应用现状
传统固定顺序流水线智能体的短板：无法根据验证结果自适应调整流程，失败后缺少迭代闭环
赛道背景：Multi-Agent 编排平台，探索智能体调度与协同范式
1.2 国内外研究现状
大模型软件缺陷自动修复研究现状
多智能体协同、编排调度在软件工程中的相关研究
现有方案不足：多数为固定流程，缺少可验证证据驱动的自适应调度、缺少对照量化评估
1.3 研究内容与目标
构建三 Agent 协同链路，标准化测试证据结构
实现证据驱动闭环调度，设置人工复核兜底分支
在 QuixBugs-Python 数据集上，对比证据驱动调度与固定流水线调度的效果与开销
1.4 论文组织结构
2 相关基础与技术基础
2.1 Multi-Agent 编排平台
可视化编排、节点串联、条件分支、全局变量机制
2.2 软件缺陷自动修复
补丁修复范式、diff 补丁格式、单元测试验证逻辑
2.3 数据集介绍：QuixBugs-Python 子集
样本构成：buggy 源码、正确源码、配套测试脚本、样本规模
2.4 评价指标定义
修复成功率、LLM 调用次数、Token 开销、执行耗时、人工移交占比
3 证据驱动多 Agent 编排系统总体设计
3.1 总体架构设计
系统整体框图：输入样本 → 定位 Agent → 修复 Agent → 测试 Agent → 调度判断节点 → 分支（成功 / 重试迭代 / 人工复核）
3.2 智能体角色与职责定义
缺陷定位 Agent
补丁修复 Agent
测试 & 证据整理 Agent
每个 Agent：输入、输出、提示词约束、结构化输出格式
3.3 证据驱动调度规则设计（本章核心）
标准化测试证据 JSON 结构定义
调度判断逻辑、重试计数规则、最大重试上限
三条分支流转逻辑：修复成功、重试迭代、移交人工复核
3.4 对照组：固定流水线调度方案设计
流程：定位→修复→测试，仅执行一轮，无回传迭代
控制变量说明，保证对比公平
3.5 人工复核模块设计
功能：汇总全链路证据包，记录失败原因，不自动修复
