| 角色 | 现有职责 | 执行与验证权限 |
| --- | --- | --- |
| repairer 修复员 | 依据当前开发失败和知识片段输出JSON修改/说明 | 只建议允许文件；应用前由程序检查，不能改测试/命令/权限 |
| detector 检测员 | 基于实际工具证据分析失败，输出受校验字段与引用 | 不自行制造测试结果；失败类别必须与工具证据一致 |
| scheduler 调度员 | 输出结构化动作建议、理由及证据引用 | 不能覆盖程序预算、版本、权限或终止规则 |
| locator 兼容定位角色 | 需要重新定位的分支使用，结果进入后续修复输入 | 是现有额外兼容动作，不能将真实总调用数写成固定只有3次 |
| tester 确定性工具 | 真实启动pytest、核对并保存结构化证据 | 不调用LLM，不让LLM自行宣布测试通过 |

V3的三个主要模型职责不要求三家服务商或三个不同模型。旧v0.2角色配置/提示词是独立兼容输入，reviewer关闭、tester为确定性工具；不据旧草案自动宣称V3角色已获B/C签收。

## 当前实际执行链

模型/隔离前置检查 → 原始坏代码基线 → repairer → JSON与路径校验 → 单文件候选应用 → 开发pytest → detector → scheduler建议 → 程序规则决定下一步。开发通过才进入从干净起点重放最终完整文件的final_check；最终结果不再回流本轮角色。

当前证据包括run/call/phase、代码版本、测试套件版本、开发失败详情和知识citation_id。新代码不能沿用旧版本的通过；未知、未执行、缺测或证据不完整不能推进为最终成功。模型格式错误/越权输出不应用，仍保留尝试记录与预算消耗。

| 触发证据 | 程序动作与限制 |
| --- | --- |
| 断言失败或待修代码运行异常 | 在剩余预算内重新定位/修复；先区分环境错误 |
| 语法错误 | 按规则回修复，不让模型改原生测试 |
| 环境错误 | 停止自动修代码，暂停/移交环境处理 |
| 测试超时、调用/轮次/总时限耗尽 | 停止，保存已有原始结果；完整进程树清理仍须目标机验证 |
| 违规路径、测试改动或无效版本/证据 | 拒绝应用/推进并记录原因 |
| 开发通过 | 干净副本独立重跑同套冻结测试，不能直接宣布success |
| final_check失败或不完整 | 本轮结束并保留失败/不确定；不得把final反馈回流继续凑成功 |

最多3个候选，首次尝试也计入；无效输出不能免费重置。单请求、工具及总运行限额分别记录。步骤边界pause/stop已实现，当前不支持暂停后续跑、运行中追加约束或即时杀掉已发出的请求。
