# 运行配置与版本关系

核对日期2026-11-03。V3.0是需求基线；本次没有修改JSON、依赖、提示词、数据库或环境变量。配置方式见[运行指南](../00_项目导航/项目运行指南.md)。

| 版本轴 | 当前真实值/来源 | 解释 |
| --- | --- | --- |
| 项目需求基线 | [V3.0原文](../开发要求V3.0.md) | 决定核心义务，不代表所有组件都是3.0或已经稳定 |
| 旧配置/接口草案 | [agents](../../configs/agents.json)、[rules](../../configs/decision_rules.json)、[test plan](../../configs/test_plan.json)：`iteration-0.2-20261101-draft` / `0.2-20261101-draft` | 真实兼容输入，pending_BC_confirmation；不强改成V3或凭空写v0.2.0 |
| V3服务报告 | [service.report](../../app/service.py)中`schema_version=v3` | 是服务报告字段，与旧ToolResult契约分别解释 |
| 代码/里程碑版本 | Git commit、既有v1.0-*标签 | 以实际Git记录及限定验收解释，不能因数字低于3就删除或升级 |
| 文档修订 | 本次文档提交与CHANGELOG | 不改V3原文，不给历史测试自动升级版本 |
| 日期记录 | docs/daily、docs/deliveries、evidence实际日期/run_id | 编制日/安排日/实际执行日分开；不得每天改旧证据日期 |

CODE_FIX_RUN_ROOT指定实际运行根；本机默认runs/platform。CODE_FIX_API_KEY/MODEL/BASE_URL、请求时限、日费用与实际单价、LIVE_APPROVED及Docker镜像ID/EXECUTION_APPROVED均须按真实授权配置，不把示例值当批准。多机独立SQLite不形成队伍跨机器总账。

已知阻塞：跨日pending/unknown阻断与绝对请求时限待补（T-021/022）；模型/预算未确认（T-033），B机Docker资格待验（T-031）。空值/null不表示无限；未知费用不填0，不删除账本绕过。

旧v0.1裸代码与v0.2 JSON changes/new_content输出用匹配解析器；ToolRun→ToolResult、旧heldout_failed等兼容不靠文档更名自动完成。升级接口须另确认字段、生产/消费双方、兼容测试与签收，不能在治理中静默改程序。
