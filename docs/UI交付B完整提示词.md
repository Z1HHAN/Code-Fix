## 完整开发提示词 开始

你是“验链 Code Fix”项目的Python开发成员B。请结合附带三栏界面参考图，为本项目实现首版可用界面，并接入实际执行状态、配置和证据。先检查现有代码与接口，复用已经实现的模块，不另建一套互不相通的演示平台。

仓库：https://github.com/Z1HHAN/Code-Fix
先阅读scope.md、configs/agents.json、configs/decision_rules.json、docs/接口确认清单.md及现有执行代码。配置仍为草案，需要B/C确认；不得为了迁就画面静默修改协议。原day1-kit输入保留，v0.2修复员输出为JSON，解析器必须匹配。

页面实现优先沿用项目已约定的轻量Python界面方案；若项目已经使用其他UI框架，则先复用。UI读取和调用同一套流程函数，不引入额外微服务、队列或新的复杂平台。
如果执行器尚未完成，先交付标注清楚的只读日志页和缺失接口清单；没有接通的按钮禁用并解释原因，不能用模拟进度冒充真实运行。

### 一 整体布局

参考图片的白底、蓝色主按钮、浅灰卡片、三栏桌面布局。
页面标题：验链 Code Fix；副标题：Python软件缺陷修复平台。
桌面栏宽约左28%、中35%、右37%，允许合理调整；各栏内容自然滚动，不把所有细节挤成小字。
不要添加自由拖拽画布、企业权限、多模型路由、模型训练或任意仓库上传入口。

左栏“任务与配置”：填写与预览任务；运行后展示本次配置快照。
中栏“执行过程”：运行摘要、步骤、轮次历史、调度决定、暂停和约束更新。
右栏“证据与结果”：运行结论、代码版本、差异、开发测试、独立验收、证据、知识引用、用量和下载。

页面顶部右侧明确显示数据模式：
- 接真实执行器和真实记录时：真实运行记录。
- 人工演示数据时：模拟状态 · 非运行证据。
- 没有数据时：待运行。
不能只修改角标就把模拟数据当成真实记录。两种数据源不混存、不混算。

### 二 启动前与运行后必须分开

A 尚未启动：
- 用户可选择预置项目和任务、填写缺陷描述、允许路径、禁止路径、最大修复轮数。
- 任务ID绑定已登记任务，不允许随意输入宿主机路径后执行。
- 默认定位员启用、修复员启用、审查员关闭；不支持的角色组合明确禁用并说明。
- 模型名称来自实际配置，首版共用一个模型；不增加未支持的模型选择。
- 工具权限和知识来源显示实际角色配置，可展开查看；用户不能超出系统上限自行扩权。
- 未产生run_id、轮次或测试结果，显示“待运行”，不伪造编号和0失败。
- “预览配置”可用；“确认启动”只有通过预览并满足必要条件时可用。
- 暂停、继续和证据下载在没有对象时禁用并给出原因。

B 配置已预览、尚未启动：
- 展示最终生效的任务、起点版本、角色、模型、工具、知识、允许/禁止路径、轮次、测试命令档案、时间和调用预算。
- 配置错误、隔离未就绪、必需限制未确认时，明确报错并禁止启动。
- 预览不调用付费模型，不创建执行任务。
- 用户改动任何影响执行的配置后，旧预览失效，必须重新预览。
- 确认启动必须使用已预览的同一份配置，不能从页面再读取一套变化后的参数。

C 已经运行，包括正在执行、等待暂停、已暂停：
- 左栏改为本次运行的只读配置快照；不能继续随意更换任务、模型或角色。
- “预览配置”“确认启动”禁用，提示本次运行已创建，请勿重复启动。
- 顶部和中栏显示稳定的run_id，所有证据与该run_id绑定。
- 约束修改仅通过暂停后的专用操作，保留新配置版本和原始快照。
- 刷新、组件重绘、重复点击、浏览器重连不创建第二个运行或再次调用付费模型。
- 一次暂停恢复不能重置轮次、预算、耗时或run_id。

D 本次运行已结束：
- 配置与证据仍保持只读，可查看历史过程和下载已有结果。
- 显示“新建运行”入口：显式回到配置预览，再确认后生成新的run_id。
- 不能因为打开结束页面自动运行；不能在已结束run_id上偷偷恢复修复。
- 并发仅按首版能力支持。至少对同一任务、同一启动请求防重复；不扩展多用户调度系统。

### 三 左栏字段与按钮布局

按以下顺序排列：
1. 项目选择与任务选择，显示任务ID和代码起点版本。
2. 缺陷描述，多行输入。
3. 允许修改路径，每行一条。
4. 禁止修改路径，每行一条。禁止优先，系统边界优先于用户配置。
5. 最大修复轮数，默认3；其余预算放入可展开的运行限制区域。
6. 角色卡：定位员、修复员、审查员，显示简短职责及启用状态。
7. 模型名称、角色工具权限、知识来源概况。
8. 配置校验提示。
9. 底部并排“预览配置”“确认启动”；运行后保持原位置但禁用。

按钮真实状态、未实现原因与校验错误均用文字说明，不能只靠灰色区分。
模型密钥由环境配置管理，不显示在截图、日志、预览或下载中。

### 四 中栏 运行编号 当前步骤与轮次历史

中栏顶部固定摘要：
- 运行编号run_id；
- 当前运行状态；
- 当前执行步骤；
- 已用修复轮数 / 最大轮数；
- 剩余修复轮数；
- 当前代码版本code_version；
- 当前配置版本config_version。

轮次按实际修复候选生成次数计算，遵循decision_rules.json：
- 初始基线测试不计修复轮数；
- 每次请求修复员生成候选修改计一轮，格式错误或修改被拒也不能免费重置；
- 定位调用不额外占用修复轮次，但计入调用和时间预算；
- 网络有限重试单独计数，不因为UI刷新而重发；
- 准备下一轮定位时，应显示“已用1/3，准备第2轮”，不能在候选尚未生成前误记已用2轮。

主流程展示：
准备与基线测试 → 定位 → 生成修改 → 应用修改 → 开发测试 → 决策 → 独立验收 → 结束。
为贴合参考图，可将生成和应用合成视觉卡片，但须区分“候选已生成”和“修改已应用”。
绿色完成只表示该步骤完成，不能把“修改已应用”显示成“缺陷已修复”。

使用分轮时间线或可折叠轮次卡，不覆盖旧轮次：
- 初始检查：环境与基线测试。
- 第1轮：定位完成、修改已应用、开发测试失败、决策返回定位。
- 下一轮：定位进行中，历史第1轮保留。
- 每次决策显示触发证据、代码版本、失败类型、动作和理由。

失败回到定位时：
- 高亮新的定位步骤；
- 保留上一轮的完成状态和失败日志；
- 不回到重新选任务，不改变run_id、不清空历史；
- 失败后箭头指向真实下一步，而不是装饰性的固定循环。

视觉规范：蓝色为进行中，灰色为待执行，绿色为具体步骤完成/验证通过，橙色为恢复或暂停提示，红色为失败/停止。颜色必须配文字。

### 五 调度必须接真实规则

UI展示程序产生的Decision，不自行根据日志关键词猜最终状态：
- 开发断言失败：重新定位，然后在预算内修复。
- 待修代码语法错误：局部重修。
- 待修代码运行异常：重新定位，先分清不是依赖问题。
- 环境异常：暂停，等待检查，不继续让模型修改业务代码。
- 输出格式错误：不写入文件，按预算有限重修。
- 工具、时间、轮次或已配置费用上限达到：停止，保留已有结果。
- 测试超时：清理完整执行任务后停止，保留超时证据。
- 越权修改或试图改测试：拒绝应用并停止本次运行。
- 开发测试通过：进入独立验收，不能直接宣布最终成功。
- 独立验收失败：记录失败并结束，不把保留测试细节反馈给本轮修复。
- 代码已改变但证据仍属旧版本：显示旧证据失效，当前版本必须重新验证。

主界面只展示本次实际发生的分支。参考图底部“环境异常”“达到上限”两卡可以作为折叠的规则说明，不能同时伪装成本次都发生的事件。

### 六 暂停与追加约束

中栏主按钮：“请求在步骤边界暂停”。
- 点击后状态为“等待步骤边界暂停”，不能立刻显示“已暂停”。
- 当前模型或工具调用结束后，在下一个安全步骤边界暂停，不再发起下一步。
- 暂停后显示追加禁止路径输入框及“更新约束并继续”。
- 保持原允许范围，追加限制只收紧权限；不能借此扩大到其他文件或修改已经消耗的预算。
- 追加约束必须校验和预览差异，后端原子更新配置版本，写入事件记录。
- 重新检查尚未应用的候选修改。已在执行中的操作完成不等于自动回滚已应用代码；当前代码、证据、约束变化须分别显示。
- 候选合法：继续同一次运行，轮次和预算累积。
- 候选违反新约束：拒绝应用，按现有权限规则停止并保留报告。
- 环境异常造成的暂停，环境未重新确认前不能点击继续。
- 本阶段不要求即时中断流式模型请求。
- 具体能力未实现时，按钮明确禁用并标“待接入”，不要制作假交互。

### 七 右栏证据与结果

从上到下：
1. 本次运行状态：运行中、等待暂停、已暂停、成功、失败、已停止、环境异常；与后端统一映射。
2. 当前代码版本：显示任务起点与当前版本，能与选中的证据对照。
3. 修改差异：文件列表、差异与修改说明；区分候选、已应用、已拒绝，禁止把拒绝内容当实际补丁。
4. 开发测试：通过/失败/未运行/结果不确定、计数、跳过、超时、退出码、代码版本、日志入口。
5. 独立验收：同样独立展示状态；未执行明确显示未运行。
6. 调度依据：Decision ID、规则ID、失败分类、下一步、原因、证据ID。
7. 知识引用：查询、命中文档、标题、引用ID和可打开的来源。
8. 耗时与用量：实际耗时、调用次数、Token；费用不确定显示未知，不能当0元。
9. 底部按钮：查看日志、查看来源、下载报告；在修改差异区另设下载已应用修改。

查看日志使用run_id + 证据ID + code_version定位，不能打开另一任务的日志。
查看历史代码的通过结果时，醒目标“历史版本”，不能显示成当前版本通过。
独立验收只读取C提供的报告，不把保留测试源码或细节送入Agent输入。
有报告但没有有效修改时允许下载报告，禁止下载不存在的补丁。
下载失败时报告缺失内容，不生成假的成功结果。

### 八 按钮行为与防重复要求

- 预览配置：只校验和展示，不执行、不扣费。
- 确认启动：绑定预览版本，只创建一次运行。
- 请求暂停：只设置暂停请求，等待真实步骤边界。
- 更新约束并继续：只在已暂停且校验通过后提交一次更新。
- 查看日志/来源/差异：只读，不触发模型或测试。
- 下载报告/修改：只导出已有内容，不重跑任务。
- 新建运行：仅在显式操作后回到配置状态，再预览确认。

禁用按钮是第一层防护，后端仍须检查活动run_id和启动请求，不能只依赖浏览器状态。
使用启动请求标识、持久运行记录和必要的锁等轻量方法实现幂等，不强制引入数据库。
界面刷新后从真实记录恢复展示，不能把重绘当作新启动。
进程重启后若运行状态无法确认，显示待核查并阻止重复执行，不能谎称旧任务仍在正常运行。
UI自动刷新或轮询只读状态，不能重新进入执行入口。

### 九 需要的接口与事件

复用TaskSpec、AgentSpec、ToolResult、Evidence、Decision、RunSummary。
与C明确测试执行、干净副本验收、日志位置和代码版本，缺字段时在同一个PR确认后更新。
每个事件至少能定位run_id、任务、时间、事件类型、步骤，相关事件另带轮次、代码版本、证据和配置版本。
暂停与等待状态属于过程状态；RunSummary的success/failed/stopped/infra_error属于终态，不要把页面文字直接写成新协议值。

第一版可以直接调用Python服务函数、读取JSONL，不需要HTTP接口平台。
若引擎缺失，则先提供真实日志查看能力，保留未实现状态和对接列表，不另造一套随机事件来声称接通。

### 十 验收与交付

交付：
1. 实际UI代码、所需最小适配和依赖变更。
2. README安装与启动命令，注明模型密钥如何在本地配置。
3. 字段映射和缺失接口清单。
4. 启动前、运行中返回定位、等待暂停、已暂停、结束等状态截图；演示状态须标注模拟。
5. 至少一个真实run_id与日志、修改和测试证据，测试和环境由C复核。
6. 已实现/未实现清单，不能将原型图当成功能完成。

逐项检查：
- 未预览或预览过期不能启动。
- 双击启动只有一个run_id和一次实际启动。
- 运行中、等待暂停、已暂停时不能再次启动。
- 刷新、重连、重复点击不重复收费、不混入上次任务数据。
- 断言失败后新的定位步骤高亮，上一轮保留，已用轮数正确。
- 语法错误、环境异常、达到上限显示不同动作。
- 暂停只在步骤边界确认；约束生效、违规候选被拒。
- 新版本代码不能继承旧版本的通过状态。
- 开发测试通过但独立验收未执行时，不能显示最终成功。
- 失败或停止后可下载已有报告，无补丁时禁用补丁下载。
- 来源、日志与差异均能打开并对应当前选择。
- A能够按README在主执行机操作，不需要B现场补写步骤。

防重复和状态转换可用明确隔离的测试夹具验证，不为检查按钮重复付费；真实集成至少保留一次实际模型和测试证据。
先完成正确状态与数据对应，再做样式调整。未完成项如实登记。

## 给GPT生图时的用法

将参考图片和上面的完整规格一起发送，并加上以下开头：

“请作为产品原型设计师，依据附图和完整规格，生成验链平台的多状态UI设计图。本次只生成界面图，不输出代码。保持同一套三栏布局，中文简体，白底蓝色主按钮，桌面横向16:9，卡片、文字和按钮清晰。所有图片右上角标‘界面原型 · 非运行证据’，所有数据使用占位或明确演示数据。不要把不同运行状态混成一张互相矛盾的页面。请先只生成A图：尚未启动、配置待预览。后续我会逐张要求生成B图：运行中、第1轮失败后准备第2轮定位；C图：已暂停、追加约束；D图：达到上限并停止；E图：独立验收实际通过的成功状态原型。各图遵守同一规格，未运行和未知不得伪装成通过与0元。”

后续每次沿用上一张的布局，再请求其中一个状态即可。生成成功状态只表示界面设计，不能登记为项目实际成功。
A与B应以文字规格作为实现依据，图片中的错字、装饰箭头或生成偏差不修改协议。
