# 五天落地与参赛分工计划

计划日期：2026年11月1—5日。A兼原D/E，三人每天各4—5小时，总计约60—75人时；C能独立编写和调试Python。UI目前仅静态，后端和HTTP接口尚未开始，隔离环境未确认，B/C整改已通知但尚未提供复验结果。

目标是在五天内形成可复现的最小平台：定位/修复模型角色、确定性测试角色、知识输入、fixed和dynamic两套流程、真实日志页面、小批对照、demo脚本与PPT初稿。完成以证据为准，不能将材料或原型记为产品完成。

## 共同约定

- 定位/修复共用已接通的模型，输出结构化JSON；测试角色执行预登记命令，不调用模型决定是否通过；可选reviewer关闭。调度器是规则程序。
- fixed只产生1个候选；dynamic最多3个候选，即首次加最多2次重试。无效修复输出占轮数；有限网络重试另记调用和消耗。
- QuixBugs使用固定版本原生测试，Agent不生成或修改目标测试。平台自身的分类/超时/权限检查可由C编写，单独登记。
- 独立复验在干净起点应用候选，重跑同一套未修改原生测试；不称隐藏测试或额外覆盖，结果不回流本轮修复。参考实现与控制端密钥不进入Agent工作区。
- 隔离未知时可做已审阅fixture工具检查，不伪填isolation_ready，不自动执行模型候选。预算建议须确认后才生效，null不是无限。
- 知识与团队配置属于题面明确能力，本周须有最小真实接入。自由画布、多模型路由、SWE-bench、Defects4J与自动生成目标测试不进入五天任务。

## 实验口径与公开任务

固定来源为QuixBugs commit 4257f44b0ff1181dedaedee6a447e133219fcebf，任务入口见[测试计划](../configs/test_plan.json)。官方40个程序，测试在python_testcases，默认存在慢测试跳过，C须冻结测试ID、skip和timeout策略。[上游说明](https://github.com/jkoppel/QuixBugs/blob/4257f44b0ff1181dedaedee6a447e133219fcebf/README.md)

两组模型、参数、提示词模板、知识、测试和坏代码起点一致，任务/对话/补丁相互独立。dynamic可读本组前轮证据。主指标以同批全部预登记任务为分母，每任务最终通过记1，否则0；候选级比例另列。运行时环境失败、超时、未产补丁保留主表，不按成绩换题。

fixed一轮对dynamic三轮比较整套策略及成本，不能把收益全部归因于路由。11月6—10日补同预算上限对照和原scope单Agent组；实际消耗仍可能不同。正式样本先争取约10—12条预登记合格任务，视预算扩展；调参样本另列，40条环境资格可扫描并公开排除原因，不承诺全部适用或全部修好。
