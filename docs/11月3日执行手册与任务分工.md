## 可直接使用的现有入口

先按[运行文档](V3运行与接口.md)准备Python3.14和锁定依赖。下面是PowerShell示例，新检出须先创建runs父目录；复跑换输出名，保留旧日志。

```powershell
New-Item -ItemType Directory -Path runs -Force | Out-Null
.\.venv\Scripts\python.exe -B -X utf8 -m pytest -q -p no:cacheprovider --basetemp=runs/nov03-b-tmp1 --junitxml=runs/nov03-b.junit.xml
node --test tests/ui_prototype.test.cjs
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli validate-config
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli doctor
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli list-projects
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli import-quixbugs
docker version
docker info --format '{{.OSType}}'
```

C复跑使用`nov03-c-*`独立输出；只保存脱敏的环境结果，不打包密钥、Docker凭证或个人浏览器资料。导入预览不会执行公开代码。镜像构建和隔离变量的使用见运行文档，不能只把`CODE_FIX_EXECUTION_APPROVED=1`设上就宣布隔离通过。真实模型变量暂不设置；A尚未确定服务商、模型或付费额度。

通过隔离条件确认后，B/C在B机执行已登记公开题目的基线，不需要模型密钥：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli create-task --project qb-get_factors --mode baseline --idempotency-key nov03-qb-get-factors-qual-001
# 从上条实际输出复制run_id，不重复创建后假装同一条运行
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli start-task <实际run_id>
.\.venv\Scripts\python.exe -B -X utf8 -m app.cli task-report <实际run_id>
```

尖括号是说明占位，不能原样执行。当前**不存在fixed命令/模式**，B完成实现并经C复核后再添加真实命令，不能先在文档伪造入口。
