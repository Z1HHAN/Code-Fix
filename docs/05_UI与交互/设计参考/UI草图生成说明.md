# UI草图生图提示词与操作步骤

这些是早期生图模板。最终UI实现和状态逻辑以[UI交付B完整提示词](../UI交付规范.md)为准；以下模板只用于布局讨论。
三栏原型就是UI雏形：A确定信息和操作，B负责接真实配置、日志与程序。
图中任何结果均为演示占位，不是运行证据。长中文可能出现错字，A需对照本说明检查，不能直接作为精确界面规格。

## 提示词一 先生成结构草图

请为“验链 Code Fix”生成一张桌面网页应用的低保真线框图，横向16:9，白底、灰色线条、少量蓝色强调，中文简体，清晰易读。目的是供开发者确认布局，不需要装饰插画。右上角必须写“界面原型 · 非运行证据”。

页面是Python软件缺陷修复平台，固定三栏：
左栏约25%：任务与配置。包含项目选择、任务ID、缺陷描述输入框、允许修改路径、禁止修改路径、最大修复轮数默认3。角色卡只展示定位员、修复员启用，审查员关闭。显示模型名称占位、工具权限、知识来源概览。底部按钮“预览配置”“确认启动”。强调先预览再启动。
中栏约40%：执行过程。顶部显示运行编号占位。纵向步骤为准备、定位、修复、开发测试、决策、独立验收、结束。显示当前轮次、失败类型、下一步动作与原因。按钮“在步骤边界暂停”，暂停后才显示追加禁止路径的输入与“更新约束并继续”。
右栏约35%：证据与结果。分区为当前代码版本、修改差异、开发测试、独立验收、调度依据、知识引用、耗时与用量。开发测试和独立验收必须是两个独立状态区。提供查看日志、查看来源、下载报告按钮。

所有结果位置写“待运行”或“未知”，不要编造运行编号、百分比或成功成绩。文字不宜过密，可用简洁表单和卡片。不要出现自由拖拽画布、企业管理、多租户、模型训练或跨行业入口。生成一张完整页面图。

## 提示词二 生成失败分支状态

请沿用上一张验链三栏界面的布局，生成“开发测试失败后的决策状态”原型。保持简体中文和可读性，右上角写“模拟状态 · 非运行证据”。
中栏突出“开发断言失败→返回定位→准备重修”的路径；显示失败证据ID、当前代码版本、决策原因、剩余轮数的位置。右栏展开开发日志区域，独立验收显示“未运行”，不能显示绿色最终成功。
用橙色提示失败和恢复动作，用红色表示停止，用绿色只表示明确已通过的具体步骤。图内所有数值和ID使用占位符，避免伪造真实成绩。
旁边提供两个小型状态卡：“环境异常→暂停，等待检查环境”和“达到上限→停止，保留报告”。不要把环境异常画成继续请求模型重修。
这张图只演示状态，不新增功能或改变原有字段。

## 提示词三 生成用户操作流程图

请生成一张中文横向用户操作流程图，用于验链平台UI设计讨论。白底，简洁矩形和箭头，标注“操作原型 · 非运行证据”。流程：
选择任务和起点→填写缺陷与路径约束→预览角色/权限/知识/轮次配置→确认启动→查看运行编号与步骤→查看开发测试及调度证据→独立验收→下载修改和报告。
开发失败分支：语法错回修复，断言失败回定位，环境异常暂停，达到上限停止。
人工操作分支：请求暂停→到步骤边界停下→追加禁止路径→检查已有候选修改→违规拒绝并停止本次运行；合法修改继续。
强调开发测试通过不等于独立验收通过。未执行的验收显示未运行，费用无法计算显示未知。不需要真实运行数据或精美插画。

## A给B的操作规格

| 操作 | 用户输入 | 程序动作 | 页面应显示 |
| --- | --- | --- | --- |
| 预览配置 | 任务、角色、权限、约束、轮次 | 校验并生成预览，不调用付费模型 | 最终将使用的配置及错误 |
| 确认启动 | 用户确认预览 | 创建一次run_id，开始任务 | 固定运行编号与准备状态 |
| 查看过程 | 当前run_id | 读取日志，不重新运行任务 | 当前步骤、轮次与状态 |
| 查看证据 | 证据ID | 读取本次运行对应版本记录 | 原始日志、来源、代码版本 |
| 请求暂停 | 暂停请求 | 在步骤边界停止推进 | 等待边界或已暂停，不能谎称即时中断 |
| 追加约束 | 新禁止路径 | 更新配置版本，重新校验未应用候选 | 新约束、被拒修改、下一步 |
| 恢复执行 | 确认有效约束 | 从合法状态继续，预算不重置 | 延续run_id与轮次 |
| 下载结果 | 当前运行 | 导出已有差异和报告 | 结果与证据，不伪造缺失项目 |

刷新页面、切换标签或重复点击不能重复触发收费运行。新开一次运行才生成新run_id。
若今天仅实现只读日志页，则启动、暂停、继续等未实现操作明确标待实现；A在验收表登记缺口。

## A代D第一次操作清单

- [ ] 按README安装和配置，不把密钥录入截图或录屏。
- [ ] 选择准备好的任务，查看允许路径和轮数。
- [ ] 预览并启动，记下run_id。
- [ ] 找到当前步骤、失败原因、调度决定和依据。
- [ ] 打开本次修改差异、开发测试、独立验收记录。
- [ ] 尝试平台已实现的暂停与约束更新；没实现就登记未实现。
- [ ] 确认页面刷新不触发新任务。
- [ ] 保存报告；记录不理解的词、缺失步骤、报错和等待时间。

记录格式：位置｜期望行为｜实际行为｜复现步骤｜run_id｜证据链接｜负责人。
