# V3状态控制与证据一致性验收

2026年11月2日，继续队长已授权的状态机、证据记录和允许执行的测试开发。起点为`a2729f5`，开发分支仍为`codex/development-v3`；不修改main，不安装Docker，不调用付费模型。原`evidence/v3/`及C历史记录保留，不覆盖旧阶段结论。

## 实际问题与修改

- 原任务启动、结束及控制请求先提交状态，再另行保存事件。若事件写入失败，会留下状态与证据不一致的问题。现在同一SQLite事务保存两者，失败一起回滚；启动目录创建失败也不会把任务留在running状态。
- 原JSON报告分别读取任务和事件，可能在结束瞬间混合两个时间点。现在使用同一数据库读快照，不把运行中状态与随后完成的事件拼接。
- 原模型请求返回后，尚未重新检查暂停/停止，可能继续写入刚返回的候选。现在请求返回后、预检前后及测试返回后检查控制与总时限；已保存的调用记录仍保留，停止后不会应用这次模型输出。
- stop请求不再被稍后的pause降级。排队阶段收到控制时不启动测试；已进入的可信基线测试完成后保存原始结果，再登记暂停或停止。

修改范围：`app/run_store.py`、`app/service.py`、`app/workflow_v3.py`及对应测试。控制仍在步骤边界生效，不杀死正在进行的模型请求或当前测试；不实现暂停续跑、约束追加或自动重放。`interrupt-task`仍只是操作员确认旧worker停止后的登记命令，不能用它代替进程终止。正式真实模型和Docker路径仍待验证。
