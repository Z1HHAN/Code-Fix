## 3. 编号约定

- `E-xx`：证据链问题（Evidence）
- `B-xx`：已复现缺陷（Bug，有 PoC）
- `R-xx`：代码审查发现（Review，代码确认但未端到端复现）
- `G-xx`：测试/门槛缺陷（Gate）
- `U-xx`：未验证项（Unverified）
- `T-xx`：返修工单（见 07），与仓库台账 `T-0xx` 区分：本包用 `RF-xx`（Repair Fix）

## 4. 返修流程（按 AGENTS.md）

1. A 确认范围（本包 07 的"待确认"列）。
2. B 按工单改代码/门槛，提交时记录：main SHA、分支、时间、认领范围、被测 commit、命令/结果/证据、限制。
3. C 对明确 commit 本人复跑，保留"改前失败、改后通过"两份结果，不代填签收。
4. A 复核后更新台账、CHANGELOG、素材索引；分支提交、主线合入、组件通过、真实验收分别登记。
