## B-01 `final_check` 验收字节与候选版本脱钩（P1）

**现象**：`final_check` 用 `read_text()` 把候选源码读成字符串再写入最终工作区；`read_text` 的通用换行会把 CRLF 归一为 LF，最终文件字节与候选文件不同，但代码里没有"验收字节 == 候选版本"的断言。

**复现**（PoC-1）：
- 候选文件字节 `def leap(y):\r\n    return 1\r\n` → `code_version=V1`
- 模拟 `workflow_v3.py:289-290` 的 `read_text` + `apply_candidate(newline='\n')` → 最终文件为 LF → `code_version=V2 ≠ V1`
- 结果：V1 与 V2 不同，且 `final['code_version']` 仍记录 V1。

**根因**：`app/workflow_v3.py:286-291` 只做文本搬移；`app/candidates.py:30` 用 `newline='\n'` 落盘；`test()` 只比对"传入工作区的版本"与 runner 测量值，不与 `self.version` 比对。

**影响**：最终验收证据与实际上报版本解耦。若源码含语义性 CRLF（三引号字符串、字节比较），可能对 V1 判通过而实际验收 V2，或反之误判失败。

**修复**（二选一）：
```python
# A. 保字节 + 断言（推荐）
payload = (self.current / self.source).read_bytes()
apply_candidate(self.base, final_work,
                [{'path': self.source, 'new_content': payload.decode('utf-8')}],
                self.directory / 'final-patch', project=self.task['project'])
(final_work / self.source).write_bytes(payload)
if code_version(final_work, (self.source,)) != self.version:
    raise IsolationBlocked('最终验收字节与候选版本不一致')
```
```python
# B. 只加断言（改动最小，但会让 CRLF 候选直接 blocked）
if code_version(final_work, (self.source,)) != self.version:
    raise IsolationBlocked('最终验收字节与候选版本不一致')
```

**验收**：新增用例——CRLF 候选端到端跑通，断言 `final_result == 'passed'` 且 `final['code_version'] == code_version(final_work)`；再构造版本不一致，断言 `IsolationBlocked`。

## B-02 `excerpt()` 把断言期望值送进模型上下文（P1）

**现象**：`WorkflowRun.excerpt()` 只丢弃以 `E `/`> `/`assert `/`CODEFIX_REPORT:` 开头的行，并替换 `[...]` 参数；pytest 短摘要 `FAILED tests/... - assert 3 == 4` 以 `FAILED` 开头，原样通过；带缩进的 `    assert ...` 也不被 `startswith('assert ')` 命中。

**复现**（PoC-2）：构造 `stdout.txt` 含 `FAILED tests/test_leap.py::test_leap - assert 3 == 4`，调用 `WorkflowRun.excerpt(...)`，输出包含 `assert 3 == 4`。

**根因**：`app/workflow_v3.py:152-163` 的过滤是行首前缀匹配，覆盖不到摘要尾部与缩进行。

**影响**：开发证据回灌模型时，实际值/期望值一并进入上下文。模型可据此对用例硬编码，与 `AGENTS.md`"参考答案、评测工作区不得提供给 Agent"的控制相悖。本仓开发测试与 final_check 使用同一 `test_suite_version`，构成潜在假通过路径（端到端利用需结合具体题库验证）。

**修复**：
```python
return '\n'.join(
    re.sub(r'\s+-\s+assert\s.*$', ' - [assertion detail redacted]',
           re.sub(r'\[[^\]\n]*\]', '[parameters redacted]', line))
    for line in text.splitlines()
    if not line.lstrip().startswith(('CODEFIX_REPORT:', 'E ', '> ', 'assert ')))
```

**验收**：PoC-2 转为回归用例；断言 `assert 3 == 4` 不出现、`FAILED tests/...` 文件名仍保留（便于定位）。

## B-03 CODE-07 门槛恒真，实际不测"执行版本绑定"（P1）

**现象**：`acceptance_tests/test_repair_gates.py:219-242` 的断言是
`observed['executed_version'] == expected or result['verification_status'] != 'passed'`。
`fake_execute` 改的是闭包里的 `original_work`，而 `docker_runner.run()` 传给 `_execute` 的是私有快照；`code_version(work=snapshot)` 必然等于 `expected`。同时 `fake_execute` 返回的 dict 不含 `artifact_channel`，`docker_runner.py:241-242` 必然判 `evidence_channel_tampered`，于是第二分支也恒真。

**复现**（PoC-3）：把 `observed['executed_version']` 故意写成 `'sha256:0...0'`，门槛断言仍然成立；`result['failure_class']` 是 `evidence_channel_tampered`，不是版本不匹配。

**根因**：门槛同时伪造了"执行器返回值"和"证据通道"，再用 `or` 兜底，两个分支都与被测行为无关。

**影响**："执行版本绑定"是 CODE-07 的核心承诺，实际没有任何测试。归档里该门槛 25/25 通过，不能作为证据。

**修复**：
- 直接改**传入的 `work`（execution-snapshot）**里的源码字节，让 `code_version(snapshot) != expected`；
- 断言 `runner.run(...)` 抛 `IsolationBlocked`（或 `verification_status != 'passed'` 且 `failure_class != 'evidence_channel_tampered'`）；
- 去掉 `or` 兜底，并补"先失败后修复"两份结果。

**验收**：新门槛在旧代码上必须失败，在修复后通过。

## B-04 `validate_url` 不锁端口（P2）

## B-05 非 ASCII token 触发 500（P2）

**现象**：`app/api.py:45` 直接 `secrets.compare_digest(header, token)`；Python 对含非 ASCII 的 str 抛 `TypeError`。

**复现**（PoC-4）：`secrets.compare_digest('é', 'abc')` 抛 `TypeError`。
端到端 500 未能在本机复现（httpx 客户端拒绝发送非 ASCII header），但浏览器按 latin-1 发送、Starlette 按 latin-1 解码，代码路径成立。

**影响**：未认证的 `X-Codefix-Token: é` 可让请求 500（不是 403）。无鉴权绕过。

**修复**：
```python
provided = request.headers.get('x-codefix-token', '')
if not provided.isascii() or not secrets.compare_digest(provided, token):
    return JSONResponse({'detail': '会话令牌无效；刷新页面后重试'}, status_code=403)
```

**验收**：非 ASCII token 返回 403；正常 token 不变。

## B-06 `_junit_key` 不支持参数 id 含 `::`（P2）

**现象**：`c_runner/runner.py:139-142` 用 `nodeid.split('::')`，参数 id 里含 `::` 时切错。

**复现**（PoC-6）：`_junit_key('tests/test_a.py::test_x[a::b]')` 得到 `('tests.test_a.test_x[a', 'b]')`，而 pytest mangle 的结果是 `('tests.test_a', 'test_x[a::b]')`。

**影响**：合法运行会被判 `inconclusive`（"JUnit test identities differ from frozen test identities"）。当前 profile 未触发，属潜在假阴性。

**修复**：括号感知切分——只在 `[]` 深度为 0 时按 `::` 切；或让 `pytest_entry.py` 额外输出 `nodeid -> (classname, name)` 映射，避免反向拆。

**验收**：`test_x[a::b]` 与 `test_x[1]` 都得到正确的 `(classname, name)`。

## B-07 report/ZIP 与 `/events` 两套脱敏口径（P2）

**现象**：`app/run_store.py:166-179` 的 `events()` 递归丢弃 `raw_text/messages/api_key` 并截断 6000 字符；`:181-187` 的 `snapshot()` 用 `_events()` 原样返回，而 `service.report()`、`GET /report`、ZIP 内 `report.json` 都走 snapshot。

**复现**（PoC-7）：写入含 `raw_text='SECRET-PROMPT'` 的事件后，`events()` 看不到该字段，`snapshot()` 原样返回。

**影响**：网页事件流看不到的完整模型原文，会出现在报告与证据包里；同一运行两套口径，审计时无法确认哪份为准。

**修复**：`snapshot()` 复用 `trim()`；或把 `raw_text` 从事件持久化层移出，单独存 `calls/` 目录并按权限控制。

**验收**：`events()` 与 `snapshot()['events']` 对同一事件的字段集合一致；ZIP 内 `report.json` 不含 `raw_text/messages`。
