# 未验证边界与阻塞项（08）

> 这些项**不能由本次离线复核关闭**。A 排期时不要把它们和 01 的"通过"混在一起登记。

## U-01 真实 Docker 隔离（本项目核心承诺）

- 本机**未安装 Docker**（`docker` 不在 PATH）；
- 归档 `integration-verification.json` 记录 `docker_execution_performed: false`；
- 五项"真实 Docker 结论"来自 B 机，C 未能独立复跑。

**需要**：一台有 Docker 的主机 + 明确 commit + 五项逐项证据（镜像 sha256、探针输出、容器退出码、`docker cp` 结果）。

## U-02 真实模型修复链与费用

- 未授权付费调用，无 API key；
- 归档只证明"离线 stub 流程"，不证明真实模型能修好。

**需要**：A 授权额度、真实 key、`max_calls` 上限、费用对账记录。

## U-03 最终候选干净副本独立验收（T-035）

- 依赖 U-01/U-02 的结果；
- 本机无法生成"最终候选"。

## U-04 公开题原生资格（T-032）

- 需要原题仓库与评测环境；
- 本轮未触碰。

## U-05 目标机符号链接拒绝

- 本机 `tests/test_control_boundaries.py:35` 跳过（"Host does not permit creating symlinks"）；
- 归档同跳过。

**需要**：在目标 Windows 主机（有 SeCreateSymbolicLinkPrivilege）上验证。

## U-06 完整 `c_acceptance.py` 入口的原样运行

- 本机受两个沙箱限制：node 子进程 `EPERM`、`0700` 目录不可读；
- 复跑是**分步执行**（pytest / node 逐文件 / 控制脚本 / 门槛），不是入口一次跑完；
- 因此 `summary.json` 的字段（如 `stages` 顺序、`preserve_work` 结果）未在本机验证。

**需要**：不受限主机上执行 `python scripts/c_acceptance.py --out <dir>` 并核对 exit code。

## U-07 账本并发端到端（R-03）

- 需要双账号或双 worker + 真实/模拟网络延迟；
- 代码确认存在全局阻断，但未构造"第二任务 blocked"的端到端证据。

## U-08 Split 审计绕过（R-04）

- 需要 Docker + Split 路径 + 构造 >1MiB stdout 的候选；
- 属"检测绕过"而非"假通过"，优先级低于 U-01。

## U-09 单容器 `/out` 改写（R-02）

- 需要有 Docker 的恶意镜像；
- 与 U-08 同一环境，建议一起做。

## 环境限制（不属于项目缺陷）

| 限制 | 影响 | 处置 |
|---|---|---|
| 被审目录只读（DSH 沙箱） | 不能原地跑 `c_acceptance` | 复制到工作区复核 |
| `mkdir(0o700)` 目录不可读 | pytest tmp 失败 | 复跑加 shim（已在 01 披露） |
| `node --test` spawn EPERM | 23 项需逐文件跑 | 分步复现，数字一致 |
| 仓库 `.venv` 指向 `D:\python` | README 步骤不可用 | 新建 3.14.10 venv + 本地 wheelhouse |
| 无 Docker / 无 API key | U-01/U-02 无法关闭 | 另排主机与授权 |
