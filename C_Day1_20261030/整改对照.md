# C 交付整改对照

本包对应仓库分支复核报告中 C 分支的全部整改项。目标环境为 Python 3.14，选定原始真实运行 C-20261030-193201-b32afc2e，完整版本为 3.14.6。

| 复核意见 | 已实施修改 | 验证方式 |
| --- | --- | --- |
| 运行编号与版本混用 | 从同一 manifest 和原始日志重建 README、HTML、两张截图和给 B 消息 | 自动核对编号、版本、ToolRun、JUnit；查看截图 |
| 校验清单失效、链接不存在 | 冻结文件后生成索引与 SHA256 清单；提供可重复运行的校验器 | 检查文件集合、每个哈希及全部实际 Markdown 和 HTML 本地链接 |
| 重建脚本硬编码来源与签名 | 从可选 runtime_provenance 元数据读取；缺失明确显示未知 | 已重新执行重建脚本，原记录未提供来源和签名证据 |
| 普通子进程能力边界 | README 明确仅用于固定示例开发检查，不提供不可信代码隔离或完整进程树清理 | 不把参考答案验证计入模型修复成绩 |
| Python 版本统一 | 安装脚本明确 py -3.14；已有虚拟环境及运行脚本强制检查 3.14；依赖安装使用锁定文件 | 静态检查；本机未找到可用 3.14，未声称完成新的运行验收 |

原始 runs 下所有文件逐字节保留，包括历史电脑的绝对执行路径。接收方使用本机安装和运行入口，证据链接使用包内相对路径。模拟接口样例明确标注模拟，其占位 log_path 不是实际证据链接。

本包不含 B 的 run_task.py、test_api.py、TaskSpec 或 main 平台代码，因此 B 分支隔离、成功判定、API 收集副作用、预算、集成等意见尚未在本包中实施。此包不代表整个仓库已通过集成验收。

重新交付时先运行 build_handoff.py 选择真实的 3.14 记录，再由浏览器重新截图；最后运行 verify_delivery.py --freeze 和 verify_delivery.py。截图不能仅修改文件名或文字代替重建。
