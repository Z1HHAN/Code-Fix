# Filesystem isolation test evidence

## 测试目的
证明容器看到的是自己的根文件系统，根层只读，宿主机敏感文件不可访问，未声明目录没有宿主机挂载，且只有批准的临时挂载边界可写。

## 执行命令

~~~bash
CONTAINER=docker-isolation-test
docker inspect $CONTAINER --format 'ReadonlyRootfs={{.HostConfig.ReadonlyRootfs}} Mounts={{json .Mounts}} Binds={{json .HostConfig.Binds}} Tmpfs={{json .HostConfig.Tmpfs}}'
docker exec $CONTAINER cat /etc/hostname
docker exec $CONTAINER ls -1A /
docker exec $CONTAINER cat /etc/shadow
docker exec $CONTAINER sh -c 'test ! -e /host/etc/passwd; echo canary_absent=$?'
docker exec $CONTAINER sh -c 'test ! -e /var/run/docker.sock; echo socket_absent=$?'
docker exec $CONTAINER touch /etc/evidence-must-fail
docker exec $CONTAINER touch /work/evidence-must-fail
docker exec $CONTAINER sh -c 'touch /tmp/evidence-write && rm -f /tmp/evidence-write && echo tmpfs_write_ok'
docker exec $CONTAINER mountpoint /tmp
docker exec $CONTAINER mountpoint /run
~~~

## 预期结果
- ReadonlyRootfs=true，Mounts 为空，Binds 为空，Tmpfs 仅包含 /tmp 与 /run；
- /etc/hostname 为容器自身短 ID，根目录为镜像内容而非宿主机；
- /etc/shadow 不可读；/host/etc/passwd 与 /var/run/docker.sock 均不存在；
- /etc 与 /work 写入失败（根层只读）；
- /tmp 可写且 /tmp、/run 均为挂载点。

## 结论
PASS：根文件系统为只读（ReadonlyRootfs=true），未配置任何 bind mount 或宿主机卷（Mounts=[]、Binds=null），/etc/shadow 不可读，宿主机 canary 路径与 Docker socket 均不存在，/etc 与 /work 写入被内核以 Read-only file system 拒绝，/tmp 与 /run 按声明可写且确为挂载点。
