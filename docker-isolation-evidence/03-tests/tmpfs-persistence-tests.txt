# tmpfs 持久化测试证据

## 测试目的
证明容器内可写目录只有 tmpfs：写入的数据随容器销毁而消失，不会跨容器实例持久化。

## 执行命令
~~~bash
docker compose -f 01-config/compose.yaml up -d --no-deps --force-recreate isolation-test
docker inspect docker-isolation-test --format '{{json .HostConfig.Tmpfs}}'
docker exec docker-isolation-test sh -c 'echo persistence-probe > /tmp/persistence-probe.txt; cat /tmp/persistence-probe.txt'
docker rm -f docker-isolation-test
docker compose -f 01-config/compose.yaml up -d --no-deps isolation-test
docker exec docker-isolation-test sh -c 'test -e /tmp/persistence-probe.txt; echo test_e_exit=$?'
~~~

## 预期结果
- `/tmp`、`/run` 为 tmpfs 挂载，根文件系统只读；
- 第一次容器实例写入成功；
- 销毁后用同一 compose 启动的新实例中该文件不存在（`test -e` 返回 1）。

## 结论

PASS：实例 1 写入 `/tmp/persistence-probe.txt` 成功；销毁容器后以同一 `01-config/compose.yaml` 启动的实例 2（容器 ID 不同）中该文件不存在，`test -e` 返回 1。证明写入点仅为 tmpfs，随容器销毁回收，不具备跨实例持久化能力。
