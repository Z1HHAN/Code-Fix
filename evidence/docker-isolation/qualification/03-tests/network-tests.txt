# Network isolation test evidence

## 测试目的
证明测试容器拥有独立 network namespace，未发布宿主机端口，网络为 internal: true 的独立 bridge（无默认路由、无上游 DNS），缺少 CAP_NET_ADMIN 无法改网络配置；同组 peer 可达证明 bridge 内通信正常，同时容器内无法访问外部网络。

## 执行命令

~~~bash
CONTAINER=docker-isolation-test
PEER=docker-isolation-peer
docker inspect $CONTAINER --format 'NetworkMode={{.HostConfig.NetworkMode}} Ports={{json .NetworkSettings.Ports}} PortBindings={{json .HostConfig.PortBindings}} Networks={{json .NetworkSettings.Networks}}'
docker exec $CONTAINER readlink /proc/1/ns/net
docker run --rm --network host --entrypoint /bin/sh docker-isolation-evidence:test-current -c 'readlink /proc/1/ns/net'
docker exec $CONTAINER ip -brief addr
docker exec $CONTAINER ip route
docker inspect $PEER --format 'Running={{.State.Running}} Status={{.State.Status}} IP={{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}} Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
docker exec $PEER sh -c "netstat -ltn 2>/dev/null | grep ':8080' || ss -ltn 2>/dev/null | grep ':8080'"
docker exec $CONTAINER nc -zvw 3 $PEER 8080
docker exec $CONTAINER wget -T 5 -q -O- http://$PEER:8080/
docker exec $CONTAINER ip link add evidence-test type dummy
docker exec $CONTAINER nc -zvw 3 1.1.1.1 443
docker exec $CONTAINER wget -T 5 -q -O- http://example.com
docker exec $CONTAINER nslookup example.com
docker port $CONTAINER
~~~

## 预期结果
- peer 为 running 且监听 8080；
- 主容器访问同组 peer:8080 成功并返回 HTTP 200 响应体 READY；
- 容器 net namespace 与 host-network 参照容器不同；
- Ports/PortBindings 为空，docker port 无输出；
- ip route 只有 172.18.0.0/16 直连路由，没有 default 路由；
- ip link add 因缺少 CAP_NET_ADMIN 失败；
- 容器内直连外部 IP、按域名访问外网均失败，DNS 解析失败。

## 结论
网络隔离判据 PASS：

- 主容器 → 同组 peer：可达（`nc` 返回 `open`，HTTP 返回 `READY`），证明 `internal` bridge 内通信正常。
- 主容器 → 外网（`1.1.1.1:443` / 域名解析）：不可达（IP 直连为 `Network unreachable`，域名解析失败），证明外网隔离生效。
- 这两条合起来证明 `internal: true` 按设计工作，不是 bug；同组容器互通与外网隔离并不矛盾。

补充：容器 net namespace 与 host-network 参照不同，未发布宿主机端口，路由表无 default route，且 `ip link add` 因无 CAP_NET_ADMIN 被拒绝。

敏感信息处理：保留 network mode、namespace、容器内私有 IP（172.18.0.0/16 为 Docker 默认 bridge 地址段，非客户内网）与退出码；未包含宿主机真实内网地址、代理地址或内部域名。
