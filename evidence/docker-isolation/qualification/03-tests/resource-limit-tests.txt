# 资源限制测试证据（CPU 配额 / 内存上限）

## 测试目的
用 `docker inspect` 核对声明的资源限制，并用 `docker stats` 与 cgroup v2 内核计数实测 CPU 配额和内存上限确实生效，防止单容器耗尽宿主机资源。

## 执行命令
~~~bash
docker inspect docker-isolation-test --format 'NanoCpus={{.HostConfig.NanoCpus}} CpuQuota={{.HostConfig.CpuQuota}} CpuPeriod={{.HostConfig.CpuPeriod}} Memory={{.HostConfig.Memory}} MemorySwap={{.HostConfig.MemorySwap}} PidsLimit={{.HostConfig.PidsLimit}}'
docker stats --no-stream --format '{{.Name}}|cpu={{.CPUPerc}}|mem={{.MemUsage}}|memperc={{.MemPerc}}|pids={{.PIDs}}' docker-isolation-test
docker exec docker-isolation-test sh -c 'timeout 10 yes >/dev/null'
docker exec docker-isolation-test cat /sys/fs/cgroup/memory.events
docker exec docker-isolation-test sh -c 'y=0123456789abcdef0123456789abcdef; x=$y; while :; do x=$x$x; done'
docker inspect docker-isolation-test --format 'Status={{.State.Status}} OOMKilled={{.State.OOMKilled}} RestartCount={{.RestartCount}}'
~~~

## 预期结果
- `NanoCpus=500000000`（0.50 CPU）、`Memory=268435456`（256 MiB）、`MemorySwap=268435456`（禁止额外 swap）、`PidsLimit=128`；
- 单线程忙循环时 `docker stats` 的 `CPUPerc` 收敛在 50% 附近，而不是 100%；
- 内存压测进程被 cgroup OOM 杀死（`docker exec` 退出码 137），`memory.events` 的 `oom_kill` 计数递增，`memory.peak` 达到 `memory.max`；
- 压测结束后 CPU 回落，容器仍为 running（限制生效但不影响正常使用）。

## 结论

PASS：`docker inspect` 显示 `NanoCpus=500000000`（0.50 CPU）、`Memory=268435456`、`MemorySwap=268435456`、`PidsLimit=128`，与 `01-config/compose.yaml` 声明一致。单线程忙循环期间 `docker stats` 的 CPU 占用收敛在 50% 附近（5/8 个样本落在 40%–60%，无样本超过 90%），压测结束后回落。内存压测进程持续分配直至被 cgroup OOM 杀死，`docker exec` 退出码 137（128+SIGKILL），内核 `memory.events` 的 `oom_kill` 计数由 0 增至 1，`memory.peak` 达到 268435456 字节（`memory.max`=268435456）。CPU 配额与内存上限均实测生效。

说明：`docker stats` 的 `CPUPerc` 为采样窗口内的平均占用，0.50 单核算力下理论峰值为 50%；宿主机调度抖动会带来几个百分点偏差。
说明：被 OOM 杀死的是 `docker exec` 启动的压测进程，容器 PID 1 仍存活，因此 `State.Status=running`；Docker 的 `State.OOMKilled` 反映 cgroup 最近一次 OOM 事件，与内核 `memory.events` 计数互相印证。

敏感信息处理：仅包含容器名、资源数值与退出码，不含宿主机 CPU 型号、进程列表或账户信息。
