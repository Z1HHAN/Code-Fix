# Permission isolation test evidence

## 测试目的
证明容器以非 root 身份运行，Linux capabilities 已裁剪，特权模式关闭，seccomp 默认过滤器在内核态生效，并且挂载、加载内核模块和根文件系统写入等越权操作被拒绝。

## 执行命令

~~~bash
CONTAINER=docker-isolation-test
docker exec $CONTAINER id
docker exec $CONTAINER capsh --print
docker inspect $CONTAINER --format 'Privileged={{.HostConfig.Privileged}} CapDrop={{json .HostConfig.CapDrop}} CapAdd={{json .HostConfig.CapAdd}} SecurityOpt={{json .HostConfig.SecurityOpt}} ReadonlyRootfs={{.HostConfig.ReadonlyRootfs}} UsernsMode={{.HostConfig.UsernsMode}}'
docker exec $CONTAINER grep -E '^(Uid|CapEff|CapBnd|NoNewPrivs|Seccomp|Seccomp_filters):' /proc/1/status
docker exec $CONTAINER sh -c 'mkdir -p /tmp/mount-test; mount -t tmpfs tmpfs /tmp/mount-test'
docker exec $CONTAINER modprobe dummy
docker exec $CONTAINER touch /etc/evidence-must-fail
docker exec $CONTAINER sh -c 'touch /tmp/evidence-write && rm -f /tmp/evidence-write && echo tmpfs_write_ok'
~~~

## 预期结果
- UID/GID 为 10000，UID 不为 0；
- CapEff/CapBnd 为全 0，尤其没有 CAP_SYS_ADMIN、CAP_NET_ADMIN、CAP_SYS_MODULE；
- Privileged=false、CapDrop 包含 ALL、ReadonlyRootfs=true、SecurityOpt 仅含 no-new-privileges:true；
- Seccomp=2（SECCOMP_MODE_FILTER）且 Seccomp_filters=2，与 Engine 默认 profile 基线一致；
- mount、modprobe、根层写入均返回非零；声明的 /tmp 写入成功。

## 结论
PASS：
- `id` 显示 uid=gid=10000(evidence)，非 root；
- `capsh --print` 的 Current/Bounding/Ambient 集合为空，CapEff/CapBnd 全 0；
- `HostConfig.Privileged=false`、`CapDrop=["ALL"]`、`ReadonlyRootfs=true`、`SecurityOpt=["no-new-privileges:true"]`；
- 内核态 `/proc/1/status` 给出 `NoNewPrivs=1`、`Seccomp=2`、`Seccomp_filters=2`，与 Engine 默认 profile 基线一致，且区别于 unconfined / privileged 基线的 1 个过滤器；
- mount（exit 非 0）、modprobe（exit 非 0）、根层写入（Read-only file system）均被拒绝；/tmp 按声明可写。
