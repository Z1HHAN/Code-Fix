## 如何运行

在仓库根目录使用Python3.14；C执行器会检查版本。先安装锁定依赖，再启动本机服务：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m app.cli doctor
.\.venv\Scripts\python.exe -m app.cli validate-config
.\.venv\Scripts\python.exe -m app.cli serve --port 8000
```

打开[本机页面](http://127.0.0.1:8000/)。可信闰年baseline预期3通过1失败，属于缺陷复现，final未运行，不代表模型已经修复。服务仅供本机；API字段和写操作令牌规则以接口规范为准。

## 如何协作与更新

B负责实现及执行机，C负责明确commit的测试/复核与证据，A负责范围、状态同步和合并。每次拉取记录基线及认领T-ID；在`codex/`开发分支提交，标题用“类型(范围): 具体动作”，正文说明任务、改动原因、实际验证和限制。每次提交都在固定交付日志追加记录，PR引用记录ID。A复核后正常合入main，核对远端SHA并同步台账、计划和受影响规范。详见[AGENTS](AGENTS.md)与[PR模板](.github/pull_request_template.md)。

旧10月30日、11月1/2日资料的有效未完事项沿用任务ID结转；完成项保留代码/测试/验收证据并退出待办。43项任务的三种状态独立登记，不因改名或日期变新就勾选完成。旧daily/deliveries已归入历史，后续不再增加同类日期文件；实际时间写在固定日志条目中，原始运行证据仍用独立run_id保留。
