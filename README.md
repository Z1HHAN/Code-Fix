## 如何运行

需要 Python 3.14：`c_runner` 在真实执行前会硬性校验解释器版本，3.13 及以下直接判 `environment_error`。请用该版本的解释器在仓库根目录创建虚拟环境，再安装锁定依赖启动。Windows 可用 `py -3.14`，或把下面的 `python` 换成你自己的 3.14 可执行文件：

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m app.cli doctor
.\.venv\Scripts\python.exe -m app.cli validate-config
.\.venv\Scripts\python.exe -m app.cli serve --port 8000
```

> 若仓库里已有旧 `.venv` 是用别的 Python 版本创建的（例如本机默认的 3.13），对已存在的目录再跑 `venv` **不会**换解释器，需要用 `py -3.14 -m venv --clear .venv` 重建，或先删除该目录再创建。仓库不跟踪 `.venv`，重建不涉及任何已提交内容。排查时先确认 `.\.venv\Scripts\python.exe -V` 输出 3.14。

打开[本机工作台](http://127.0.0.1:8000/)，从“新建任务”创建，再明确启动。服务仅供本机，端口范围1024–65535，不支持0随机分配；最多同时接纳2项后台任务，容量满时启动返回503，任务保持未启动，可稍后重试。

可信闰年baseline预期3通过1失败，这是缺陷复现。公开题、候选及final须通过隔离前置检查，执行器不会回退宿主。旧`live_env`须显式指定服务商和白名单地址。配置、环境变量及硅基流动双账号接入见[项目运行指南](docs/2026-11-03_项目持续维护/项目运行指南.md)。

模型与配置现支持角色账号/模型选择、任务上限、结构校验及保存为新配置；新建任务可引用保存版本，历史记录保持只读。费用与条件读取本项目估算账本和本机状态，保存不代表模型/隔离通过。使用步骤见[项目运行指南](docs/2026-11-03_项目持续维护/项目运行指南.md)；本轮限定验证见固定台账040。

## 如何测试

平台回归使用已审查的仓库测试与可信夹具。Windows每次选择一个未使用的短临时目录：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m pytest -q --basetemp=runs/pcheck-new -p no:cacheprovider
node --test tests/ui_prototype.test.cjs tests/ui_budget.test.cjs tests/ui_trace.test.cjs tests/ui_architecture.test.cjs
```

完整C入口默认要求干净Git提交；`--allow-dirty`仅供开发检查。25项门槛及执行前置见[测试与验收计划](docs/2026-11-03_项目持续维护/当前测试与验收计划.md)。模拟模型/执行器的组件结果与真实修复、独立验收分别记录，不能互相替代。
